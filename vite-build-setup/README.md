# Build lab · настройка сборки на Vite

Небольшая страница на HTML, CSS и JavaScript, демонстрирующая рабочую сборку,
dev-сервер и автоматические проверки качества. Счётчик на странице позволяет
проверить JavaScript в режиме разработки и в готовой сборке.

## Быстрый старт

Нужен Node.js 22.22.2+, 24.15.0+ или 26+. Рекомендуется актуальная версия ветки
24; `.nvmrc` содержит `24`, CI использует её же. Локально проверено на 26.10.0.

Из корня репозитория:

```bash
cd vite-build-setup
npm ci
npm run dev
```

Откройте адрес из терминала: по умолчанию http://127.0.0.1:5173.
Если порт занят, Vite выберет следующий доступный. В режиме разработки изменения
в исходниках подхватываются автоматически.

## Команды

Все команды выполняются в `vite-build-setup/`.

| Команда                | Что делает                                                                      |
| ---------------------- | ------------------------------------------------------------------------------- |
| `npm run dev`          | Запускает локальный dev-сервер                                                  |
| `npm run build`        | Собирает HTML/CSS/JS и favicon в `dist/`                                        |
| `npm run preview`      | Показывает уже собранный проект, обычно на порту 4173                           |
| `npm run lint`         | Проверяет JavaScript с ESLint; предупреждения тоже завершают проверку с ошибкой |
| `npm run lint:fix`     | Применяет автоматические исправления ESLint                                     |
| `npm run format`       | Форматирует исходники, конфигурации, README и workflow с Prettier               |
| `npm run format:check` | Проверяет форматирование без изменения файлов                                   |
| `npm run check`        | Последовательно запускает lint, format:check и build                            |

`preview` не собирает проект и не является production-сервером. Перед ним выполните:

```bash
npm run build
npm run preview
```

## Структура и сборка

```text
vite-build-setup/
  src/
    index.html          # точка входа, подключает main.js как ES-модуль
    main.js             # импорт CSS и логика счётчика
    styles.css          # оформление, адаптивность, видимый фокус
    favicon.svg         # локальный ресурс, тоже обрабатывается Vite
  dist/                 # результат build; не хранится в Git
    index.html
    assets/             # CSS, JS и ресурсы с хешами в именах
  vite.config.js
  eslint.config.js
  .prettierrc.json
  .prettierignore
  .gitignore
  .nvmrc
  package.json
  package-lock.json
  README.md
```

В `vite.config.js` корень приложения (`root`) — `src/`, выходная папка — соседняя
`dist/`. Оба пути вычисляются относительно конфигурационного файла. HTML ссылается
на `/main.js`, а JavaScript импортирует CSS. При сборке Vite обрабатывает HTML,
собирает и минимизирует CSS/JS, обновляет ссылки на выходные файлы. Для очистки
только папки этого проекта `dist/` перед сборкой включён `emptyOutDir`.

Шрифты подключены через Google Fonts; при отсутствии интернета используются
системные sans-serif. Бэкенд, React и база данных не требуются.

## Качество кода и CI

ESLint использует flat config в `eslint.config.js` и рекомендованные правила
`@eslint/js`, с браузерными глобальными переменными для исходников и Node.js — для
конфигураций. Он обнаруживает, например, неопределённые переменные и неиспользуемые
объявления. Prettier отвечает за форматирование HTML/CSS/JS/JSON/Markdown/YAML.
Правила форматирования не дублируются в ESLint. Сгенерированные `dist/`,
`node_modules/` и автоматически создаваемый npm `package-lock.json` исключены из
Prettier; `dist/` и `node_modules/` также исключены из ESLint.

Workflow находится **в корне репозитория**:
`.github/workflows/vite-build-setup.yml`. Он запускается при pull request с
изменениями проекта или workflow, при push таких изменений в `main`, а также
вручную. В CI выполняются checkout, установка Node.js, `npm ci` и `npm run check`.
При любой ошибке job завершается неуспешно. Успешная сборка доступна как артефакт
`vite-build-setup-dist` в GitHub Actions в течение 7 дней; автоматического деплоя нет.
Версии Actions зафиксированы полными SHA, зависимости — lock-файлом.

## Как проверить

1. Запустить dev-сервер, проверить стили, favicon и статус «JavaScript на связи».
2. Нажать плюс, минус и «Сбросить»: счётчик и прогресс меняются. Диапазон — 0–10;
   на границах соответствующие кнопки недоступны.
3. Изменить текст или CSS в `src/` — браузер покажет обновление.
4. Выполнить `npm run check`; затем `npm run preview` и проверить страницу сборки.
5. Для проверки ESLint временно добавить в JS обращение к неопределённой переменной:
   `npm run lint` должен вернуть ненулевой код. После проверки удалить эту строку.
6. Для проверки Prettier временно нарушить форматирование: `npm run format:check`
   должен завершиться с ошибкой. Исправить через `npm run format`.
7. В PR открыть проверку `Lint, format and build` и убедиться, что она зелёная.
